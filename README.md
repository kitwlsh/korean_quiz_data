# KDailyUtil 퀴즈 데이터 저장소

KDailyUtil 앱에서 사용하는 퀴즈 데이터를 자동으로 생성하고 관리하는 저장소입니다.

> ❗ **이 저장소가 멈추면 앱의 「오늘의 퀴즈」가 늙는다.**
> 2026-09-04부터 앱이 매일 새 문항을 기대하는 구조가 됐다(하루치 5문제 · 「새 문제 N개」 표시).
> 그래서 이 로봇은 **조용히 죽으면 안 된다** — 아래 §🛡 가 그 대비다.

## 🤖 AI 자동 업데이트 시스템

본 저장소는 GitHub Actions를 통해 매일 자동으로 새로운 퀴즈를 생성합니다.

- **실행 스크립트**: `update_quiz.py`
- **사용 모델**: 후보를 차례로 시도 — `gemini-flash-latest` → `gemini-3.5-flash` → `gemini-3.6-flash`
- **업데이트 주기**: 매일 자정 (UTC 00:00)
- **생존 신호**: `last_run.json` (매 실행마다 갱신 — 성공/실패, 쓴 모델, 누적 문항 수)
- **데이터 분류**:
  - `korean.json`: 우리말 겨루기 (맞춤법, 고유어, 사자성어)
  - `trend.json`: 트렌드 말하기 (신조어, 유행어)
  - `knowledge.json`: 상식 백과 (역사, 과학, 시사)
  - `travel.json`: 세계 여행 (국가수도, 국기, 명소)

## 🛡 조용히 죽지 않게 하는 장치 (2026-09-04 추가)

이 로봇은 오랫동안 **실패해도 아무도 모르는** 구조였다. 세 가지를 넣어 막았다.

### 1. 모델을 하나만 박아두지 않는다
예전에는 `gemini-2.5-flash`가 코드에 박혀 있었다. **하필 그 모델이 KDailyUtil 앱에서
신규 계정 404로 죽었던 모델**이다(2026-08-12 장애). 구글이 모델을 내리는 날 이 로봇도 같이 죽는다.

- 404(모델 없음)·503(과부하) → **다음 후보로 넘어간다**
- 429(할당량)·키 오류 → 모델을 바꿔도 소용없으므로 **즉시 중단**하고 실패로 알린다

### 2. 실패하면 이슈가 열린다
워크플로가 실패하면 **`🚨 퀴즈 자동 업데이트 로봇 실패` 이슈**가 자동으로 만들어진다.
이미 열려 있으면 새로 만들지 않고 댓글만 단다(이슈 폭탄 방지).

### 3. 매일 커밋한다 (생존 신호)
GitHub은 **60일간 활동이 없는 저장소의 예약 워크플로를 자동으로 끈다.**
로봇이 실패하거나 새 문제가 안 나오는 날이 이어지면 커밋이 끊기고, 그대로 두 달이 지나면
**스케줄 자체가 꺼져 사람이 되살릴 때까지 영구 정지**한다.

그래서 `last_run.json`을 매 실행마다(실패해도) 갱신하고 커밋한다.
덕분에 **파일 하나만 열어 보면 로봇이 살아 있는지 알 수 있다**:

```json
{
  "status": "ok",
  "ranAtUtc": "2026-09-04T00:05:00+00:00",
  "model": "gemini-flash-latest",
  "savedThisRun": 3,
  "totalAll": 505
}
```

## 🔧 비상 레버 — 모델을 코드 수정 없이 갈아끼우기

후보 모델이 전부 막히면 코드를 고칠 필요 없이 **저장소 변수**로 지정할 수 있다.

1. GitHub 저장소 → **Settings → Secrets and variables → Actions → Variables** 탭
2. `QUIZ_MODEL` 이름으로 쓰고 싶은 모델명을 넣는다 (예: `gemini-3.6-flash`)
3. Actions에서 워크플로를 수동 실행해 확인

값이 비어 있으면 기본 후보 목록을 쓴다. 문제가 풀리면 변수를 지워 원상복구한다.

## 🛠 수동 업데이트 방법

새로운 문제를 즉시 생성하고 싶다면 다음 단계를 따르세요:

1. GitHub 저장소의 **[Actions]** 탭으로 이동합니다.
2. **'매일 퀴즈 업데이트 로봇'** 워크플로우를 선택합니다.
3. **[Run workflow]** 버튼을 클릭하여 즉시 실행합니다.

## 📌 참고 사항

- 데이터 품질 게이트는 `validate.py`가 맡는다. 불량 데이터가 하나라도 있으면 **푸시 자체가 막힌다**
  (과거 사고: `type` 오타 하나로 「상식 백과」 100문항이 앱에서 통째로 안 보였다).
- 모델 후보를 바꾸려면 `update_quiz.py`의 `MODEL_CANDIDATES`를 고친다.
  단 **실재하지 않는 모델을 후보에 넣지 말 것** — 폴백 한 칸이 헛돌게 된다(앱에서 실제로 겪은 문제).
