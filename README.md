# KDailyUtil 퀴즈·지문 데이터 저장소

KDailyUtil 앱에서 사용하는 **퀴즈 문항과 읽기 지문**을 자동으로 생성하고 관리하는 저장소입니다.

> ❗ **이 저장소가 멈추면 앱의 「오늘의 퀴즈」가 늙는다.**
> 2026-09-04부터 앱이 매일 새 문항을 기대하는 구조가 됐다(하루치 5문제 · 「새 문제 N개」 표시).
> 그래서 이 로봇은 **조용히 죽으면 안 된다** — 아래 §🛡 가 그 대비다.

## 🤖 AI 자동 업데이트 시스템

본 저장소는 GitHub Actions를 통해 매일 자동으로 새로운 퀴즈를 생성합니다.

- **실행 스크립트**: `update_quiz.py`
- **사용 모델**: 후보를 차례로 시도 — `gemini-flash-latest` → `gemini-3.5-flash` → `gemini-3.6-flash`
- **업데이트 주기**: 매일 자정 (UTC 00:00)
- **생존 신호**: `last_run.json` (매 실행마다 갱신 — 성공/실패, 쓴 모델, 누적 문항 수)
- **데이터 분류**:
  - `korean.json`: 우리말 겨루기 (맞춤법, 고유어, 사자성어)
  - `trend.json`: 트렌드 말하기 (신조어, 유행어)
  - `knowledge.json`: 상식 백과 (역사, 과학, 시사)
  - `travel.json`: 세계 여행 (국가수도, 국기, 명소)

## 📖 읽기 지문 로봇 (2026-09-07 추가)

앱의 「빠른 독서 훈련」 지문은 오랫동안 **앱에 하드코딩된 19편**뿐이었다. 매일 하면 19일에 한 바퀴가 돌고,
그 뒤로는 재독이라 **WPM 추이 그래프가 실력이 아니라 «몇 번째 재독인가»를 그리게** 된다. 그래서 공급원을 만들었다.

- **실행 스크립트**: `update_passages.py` (퀴즈와 **별도 스텝**)
- **생산량**: 하루 **1편** — 🔴 3편 이상 만들지 않는다(소비 속도를 넘으면 «못 본 지문»이 쌓여 부담이 된다)
- **규격**: 본문 150~250자 · 제목 20자 이내 · 17개 주제를 날짜로 로테이션
- **저장 파일**: `passages_<연도>.json` — 🔴 **연도로 쪼갠다.** 앱은 동기화 때마다 파일 전체를 다시 받으므로
  (조건부 요청이 없다) 한 파일에 계속 쌓으면 퀴즈처럼 매번 수백 KB를 받게 된다
- **생존 신호**: `last_run.json`의 **`passages` 블록**(퀴즈 블록과 별도 — 지문만 실패한 날도 구별된다)
- **저작권**: AI가 새로 쓴 창작 산문만. 프롬프트에 «실존 작품·기사·가사의 재현·요약·번안 금지», «실존 인물·상표 금지»를 명시

> 🔴 **왜 `update_quiz.py`에 넣지 않았나**: 퀴즈 생성이 실패해도 지문은 저장되어야 하고 그 반대도 되어야 한다.
> 한 스크립트·한 API 호출에 둘을 섞으면 한쪽 실패가 다른 쪽을 끌고 죽는다.
> ⚠️ 워크플로에서 **지문 스텝은 퀴즈 스텝보다 뒤**에 있어야 한다 — 퀴즈가 `last_run.json`을 새로 쓰고,
> 지문이 그 위에 자기 블록만 얹는 구조다.

## 🛡 조용히 죽지 않게 하는 장치 (2026-09-04 추가)

이 로봇은 오랫동안 **실패해도 아무도 모르는** 구조였다. 세 가지를 넣어 막았다.

### 1. 모델을 하나만 박아두지 않는다
예전에는 `gemini-2.5-flash`가 코드에 박혀 있었다. **하필 그 모델이 KDailyUtil 앱에서
신규 계정 404로 죽었던 모델**이다(2026-08-12 장애). 구글이 모델을 내리는 날 이 로봇도 같이 죽는다.

- 404(모델 없음)·503(과부하) → **다음 후보로 넘어간다**
- 429(할당량)·키 오류 → 모델을 바꿔도 소용없으므로 **즉시 중단**하고 실패로 알린다

### 2. 실패하면 이슈가 열린다
워크플로가 실패하면 **`🚨 퀴즈 자동 업데이트 로봇 실패` 이슈**가 자동으로 만들어진다.
이미 열려 있으면 새로 만들지 않고 댓글만 단다(이슈 폭탄 방지).

### 3. 매일 커밋한다 (생존 신호)
GitHub은 **60일간 활동이 없는 저장소의 예약 워크플로를 자동으로 끈다.**
로봇이 실패하거나 새 문제가 안 나오는 날이 이어지면 커밋이 끊기고, 그대로 두 달이 지나면
**스케줄 자체가 꺼져 사람이 되살릴 때까지 영구 정지**한다.

그래서 `last_run.json`을 매 실행마다(실패해도) 갱신하고 커밋한다.
덕분에 **파일 하나만 열어 보면 로봇이 살아 있는지 알 수 있다**:

```json
{
  "status": "ok",
  "ranAtUtc": "2026-09-04T00:05:00+00:00",
  "model": "gemini-flash-latest",
  "savedThisRun": 3,
  "totalAll": 505
}
```

## 🚑 실패했을 때 — 로그부터 뒤지지 말 것

이 로봇은 **실패해도 사유를 남기게** 만들어져 있다. 순서대로 보면 대개 여기서 끝난다.

1. **`last_run.json`** (저장소 첫 화면) — `"status"`와 `"error"`에 사유가 그대로 있다.
   🔴 **퀴즈(최상위)와 지문(`passages` 블록)이 따로 적힌다** — 한쪽만 실패할 수 있다
2. **Issues 탭** — 실패하면 「🚨 퀴즈 자동 업데이트 로봇 실패」 이슈가 자동으로 열린다
3. Actions 탭의 실행 로그 — **위 둘로 안 풀릴 때만**

### 🔴 실패 = 모델 문제라고 단정하지 말 것

**2026-09-08에 수동 실행 3회가 연속 실패했는데 모델 문제가 아니었다.**

```
429 ... Quota exceeded for metric: ...free_tier_requests, limit: 20, model: gemini-3.8-flash
```

- **API 한도 초과(429)**였다. 이때 `QUIZ_MODEL`을 당기는 것은 **한도가 모델별일 때만** 효과가 있다
- 이 메시지가 알려준 또 하나: 우리가 쓰는 별칭 **`gemini-flash-latest`가 지금 `gemini-3.8-flash`로 풀리고,
  그 모델의 무료 한도는 20**이다. 별칭은 «한도가 짠 신모델»로도 옮겨간다
- ⏰ **언제 풀리는지는 오류의 `Please retry in ...`이 말해 준다.**
  **초 단위 = 짧은 창**(금방 풀린다) / **시간 단위 = 일일 한도**(태평양 자정 리셋 = 한국 오후 4시, 겨울 5시)
- 💡 **호출 수 참고**: 실행 1회가 쓰는 `generate_content`는 **퀴즈 1회 + 지문 1회 = 2회**뿐이고,
  429면 폴백을 더 태우지 않고 즉시 멈춘다 → **로봇이 한도를 태운 범인인 경우는 드물다.**
  같은 키를 앱이 쓰고 있다면 그쪽을 먼저 의심한다

> 앱 쪽 배경·대응 검토 = `KDailyUtil/doc/AI_KEY_NOTES.md` §3-2

## 🔧 비상 레버 — 모델을 코드 수정 없이 갈아끼우기

후보 모델이 전부 막히면 코드를 고칠 필요 없이 **저장소 변수**로 지정할 수 있다.

1. GitHub 저장소 → **Settings → Secrets and variables → Actions → Variables** 탭
2. `QUIZ_MODEL` 이름으로 쓰고 싶은 모델명을 넣는다 (예: `gemini-3.6-flash`)
3. Actions에서 워크플로를 수동 실행해 확인

값이 비어 있으면 기본 후보 목록을 쓴다. 문제가 풀리면 변수를 지워 원상복구한다.

## 🛠 수동 업데이트 방법

새로운 문제를 즉시 생성하고 싶다면 다음 단계를 따르세요:

1. GitHub 저장소의 **[Actions]** 탭으로 이동합니다.
2. **'매일 퀴즈 업데이트 로봇'** 워크플로우를 선택합니다.
3. **[Run workflow]** 버튼을 클릭하여 즉시 실행합니다.

## 📌 참고 사항

- 데이터 품질 게이트는 `validate.py`가 맡는다. 불량 데이터가 하나라도 있으면 **푸시 자체가 막힌다**
  (과거 사고: `type` 오타 하나로 「상식 백과」 100문항이 앱에서 통째로 안 보였다).
- 모델 후보를 바꾸려면 `update_quiz.py`의 `MODEL_CANDIDATES`를 고친다.
  단 **실재하지 않는 모델을 후보에 넣지 말 것** — 폴백 한 칸이 헛돌게 된다(앱에서 실제로 겪은 문제).
